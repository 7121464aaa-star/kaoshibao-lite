# M4 验收清单：响应式 PWA 打包 + Secret Gist 一键同步 + GitHub Pages 部署

> 范围（用户拍板）：**M4 全量**（PWA 打包 + 云同步 + Pages 部署指引，含 file:// 迁移说明）。
> 技术备忘落实：凭据只存 IndexedDB settings，推送剥离敏感键、拉取忽略远端 settings；

## C. 云同步核心逻辑（mock GitHub API 实测）
- [x] 推送新建 Secret Gist：POST /gists，public:false，文件 `kaoshibao-lite-snapshot.json`，请求带文件内容（✅ 实测 auth=Y/ct=Y/file 命中）
- [x] 已有 gistId → 探测云端(GET) + 覆盖(PATCH)；Authorization 与 Content-Type 均正确携带（修复过 headers 被覆盖 bug）
- [x] **推送前剥离敏感设置**：导出快照 settings 不含 sync.token（✅ tokenLeaked=false），username/gistId 非敏感可保留
- [x] **拉取忽略远端 settings**：伪造远端含恶意 token → import 后本机 token 原样保留、evilKey 不落地（✅ 实测）
- [x] 冲突=后写覆盖+自动快照：内容不同时
  - 推送覆盖 → 先存"云端旧数据"快照（kind=cloud）
  - 拉取覆盖 → 先存"本机当前数据"快照（kind=pull）
- [x] **内容级比较防误判**：两次相同内容推送不产生快照；内容一致拉取提示"云端与本机一致"（修复了原按 exportedAt 恒不等的问题）
- [x] 快照保留最近 N=5：存 6 份裁到 5、最新在前（✅ 实测 snapCountAfter6=5 / newestFirst=true）
- [x] 快照内容统一 sanitize：任何来源（含云端旧内容）落快照前剥离敏感键
- [x] 拉取覆盖/还原后 importSnapshot 只动业务 store，settings/snapshots 保留（✅ DB 实测）
- [x] 还原此快照：二次确认（含两端计数对比）→ 自动保存当前 → 覆盖 → 刷新
