## 0. 三分钟速览

| 目标 | 做法 | 谁执行 |
|---|---|---|

## 2. 部署到 GitHub Pages（一次部署，之后 push 自动更新）

### 2.1 建仓库并推源码（本会话已代做，这里留档）
```bash
git init
git add .
git commit -m "M4: PWA + Gist 一键同步 + Pages 部署"
git branch -M main
git remote add origin https://github.com/7121464aaa-star/kaoshibao-lite.git
git push -u origin main
```
> 首次推送会触发 `.github/workflows/deploy.yml`：Actions 里自动跑
> `make-icons.mjs` + `build-single.mjs`，把 `dist/` 上传为 Pages 产物。

### 2.2 开启 GitHub Pages（指向 Actions）
网页操作（`仓库 → Settings → Pages`）：
1. **Source** 选 **GitHub Actions**（不要选 branch 部署，Actions 方式产物即 dist/）。
2. 等第一次 Actions 跑完（绿色 ✓），页面显示站点地址：
   `https://7121464aaa-star.github.io/kaoshibao-lite/`
3. 打开该地址 → 应看到完整应用；DevTools → Application 里
   Manifest 可解析、Service Worker 已激活。

> **验证**：手机 Chrome/Edge 打开该 https 地址 → 菜单"添加到主屏幕/安装应用" → 得到可离线使用的图标入口。

### 2.3 以后更新
本地改完执行：
```bash
node tools/make-icons.mjs
node tools/build-single.mjs
git add -A && git commit -m "更新" && git push
```
约 1 分钟后 Pages 自动更新。

## 3. 云同步（Secret Gist 中转，一键推送 / 拉取）

### 3.1 生成只含 gist 权限的 Token（一次性）
1. GitHub → 右上头像 → **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**。
2. 勾选 **gist**（只需要这一个 scope），有效期自定，生成后**立即复制**（只显示一次）。
3. Token 形如 `ghp_…`。**不要把 token 发到聊天/仓库/文档**。

### 3.2 在应用里绑定并同步
1. 打开部署好的应用（或本地 `http://localhost` 亦可，云同步与源无关）。
2. **设置 → 云同步**：
   - GitHub 用户名：`7121464aaa-star`
   - Token：粘贴上一步的 `ghp_…`（密码框，不显示明文）
   - 点 **保存**（只写进本机 IndexedDB）
3. 点 **⬆ 推送到云端**：首次会新建一个 **Secret Gist**（public:false）并自动记住 ID；
   之后每次推送 = 覆盖该 Gist 里的 `kaoshibao-lite-snapshot.json`。
4. 另一台设备/手机（同样填同一账号同一 token）点 **⬇ 从云端拉取**：整体覆盖本机数据。

### 3.3 冲突策略（用户拍板：后写覆盖 + 自动快照）
- **推送**：若云端内容与本地不同，会先把"云端旧数据"自动存成本地快照，再覆盖云端。
- **拉取**：若内容不同，确认后先把"本机当前数据"自动存成快照，再用云端覆盖本机。
- 快照最多保留 **5 份**，在设置 → 云同步 → 自动快照列表里可 **一键还原 / 删除**。
- 误覆盖后：去列表里点"还原此快照"即可找回。

### 3.4 安全边界（务必知晓）
- token / 用户名**只存本机浏览器**（IndexedDB settings）。
- 推送到 Gist 的快照在导出时**自动剥离 token 等敏感设置**；从云端拉取时**忽略远端设置**，
  本机 token 不会被覆盖或丢失。
- Gist 是 **Secret**（非公开），但"Secret"不等于端到端加密：GitHub 工作人员/持 URL 者可见，
  请勿放入极度敏感信息；本应用只同步刷题数据，适合该等级。
- 换浏览器/清数据后 token 需重新填一次（数据可在清空前先推送云端留底）。

## 4. 从旧的 file:// 数据迁移到 PWA（一次性）

> 原因：`file://` 与 `https://` 是两个不同源，浏览器 IndexedDB 相互隔离，
> 旧双击版的数据**不会自动出现在** PWA 里，需要"导出 → 导入"。
> **手机端逐字操作（装 PWA、微信传文件、恢复/导入）见 `docs/手机端使用指引-M6.md`。**

1. **旧环境**（file:// 双击的旧版或旧浏览器）：设置 → 备份/恢复 → **⬇ 导出备份**，得到一个
   `kaoshibao-lite-备份-YYYYMMDD-HHMMSS.json`。
2. **新环境**（https PWA / 手机）：打开应用 → 设置 → 备份/恢复 → **⬆ 从备份文件恢复**；
   确认后整体替换（settings 本机凭据自动保留）。
3. 以后两端增量同步用 §3 的云同步；备份文件方式任何时候都可用（可离线、可留档）。

## 5. 本地开发联调备忘

```bash
# 1) 生成图标 + 打包 dist（PWA 站）
node tools/make-icons.mjs
node tools/build-single.mjs

# 2) 本地起服务（SW/manifest 只在 http(s) 生效）
node tools/serve.mjs 8080 dist
# 打开 http://localhost:8080/ 用 DevTools → Application 检查 PWA

# 3) 直接双击 dist/考试宝自用版.html = 单文件旧体验（自动跳过 SW 注册）
```

### 目录产物（dist/）
```
index.html              PWA 入口（单文件内联全部 CSS/JS）
考试宝自用版.html         同内容，便于双击/下载留档
manifest.webmanifest    PWA 清单（名称/图标/主题色）
sw.js                   Service Worker（离线壳缓存）
icons/                  192/512/maskable/apple-touch 图标
```

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 推送到云端报"GitHub 拒绝访问 401/403" | token 无效/过期或没勾 gist scope → §3.1 重新生成 |
| 手机上打开页面没有"添加到主屏幕" | 必须 https（Pages 已满足）；iOS Safari 用"共享 → 添加到主屏幕" |
| 拉取后题目没变 | 先确认云端确实有新内容（可能两端一致，界面会提示"云端与本机一致"） |
| 恢复备份后 token 没了？ | 不会：恢复/拉取一律保留本机 settings（含 token） |
| Pages 地址打开 404 | 检查 Settings → Pages 的 Source 是否 GitHub Actions，且 Actions 已跑绿 |
| 想完全不用云端 | 可以：纯本地/备份文件方式与之前完全一致，云同步只是可选入口 |
